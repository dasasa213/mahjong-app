# E2E テスト手順書

## 構成
- `auth/` : ログイン、ログアウト、未ログイン保護
- `user/navigation.spec.ts` : 利用者の主要画面・遷移
- `user/newgame.spec.ts` : 新規対局
- `user/matches-edit.spec.ts` : 対局編集、計算、削除確認
- `user/counter.spec.ts` : 対局カウンター、入力検証
- `admin/admin.spec.ts` : 管理者画面、アカウント・グループ入力検証
- `flows/update-flow.spec.ts` : 登録→編集→削除などDB更新を伴う一連の操作
- `support/e2e-helpers.ts` : DB安全確認、ログイン、スクリーンショット等

## 初回セットアップ（cloneした人）
Node.jsを用意し、リポジトリをclone後に以下を実行します。
```powershell
cd e2e
npm ci
npx playwright install chromium
```
ローカルアプリは必ずE2E用DBへ接続してください。テストは `/db/info` を確認し、DB名が `mahjong_test` かつDBユーザー名に `mahjong_test_user` を含む場合だけ続行します。

利用者・管理者のテスト用ログイン情報を環境変数へ設定します。
```powershell
$env:E2E_LOGIN_NAME="利用者ログイン名"
$env:E2E_LOGIN_PASSWORD="利用者パスワード"
$env:E2E_ADMIN_LOGIN_NAME="管理者ログイン名"
$env:E2E_ADMIN_LOGIN_PASSWORD="管理者パスワード"
```

## Playwrightで自動操作
アプリを起動した状態で実行します。
```powershell
cd e2e
npx playwright test --project=chromium
npx playwright show-report
```
特定機能だけ確認する場合は例として以下です。
```powershell
npx playwright test tests/user/counter.spec.ts --project=chromium
```

## 人がブラウザで画面操作して確認する場合
1. ローカルアプリをE2E用DBで起動する。
2. 利用者アカウントでログインし、利用者ホーム、新規対局、対局編集、総合成績、グラフ、対人別成績、対局カウンターを確認する。
3. 登録・編集・削除を行う機能は、操作前、確認ポップアップ、操作後を確認する。
4. 入力項目は正常値だけでなく、未入力、最小値、最大値、境界値の直前・直後、不正値を確認する。
5. 管理者アカウントでログインし、管理者ホーム、アカウント登録、グループ編集と各入力エラーを確認する。
6. 最後にテストで追加したデータが残っていないことを確認する。

## 機能追加・仕様変更したとき
機能追加時は「既存テストが通ったから完了」にはしません。変更した仕様に対応するE2Eを同じブランチで追加・修正します。

1. 変更した画面・入力項目・ボタン・ポップアップ・DB更新箇所を洗い出す。
2. 対応するspecへ正常系を追加する。新しい独立機能なら内容が分かる名前のspecを新規作成する。
3. 必須、異常系、権限差、境界値（最小/最大、その直前/直後）を追加する。
4. 新画面はスクリーンショットを追加する。削除は削除前と確認ポップアップ、更新系は必要に応じ操作後も残す。
5. DBを更新するテストは後処理を用意し、途中失敗してもテストデータを極力残さない。
6. 対象specを単体実行してから全テストを実行する。
7. HTMLレポートで Failed=0 を確認し、追加機能が既存機能を壊していないことを確認する。
8. 手動確認が必要な見た目・スマホ操作等は上記「人がブラウザで画面操作」の観点でも確認する。

### テスト配置の判断
認証は `auth/`、利用者機能は `user/`、管理者機能は `admin/`、複数画面にまたがる登録→編集→削除は `flows/`、共通処理だけを `support/` に置きます。「example」「coverage」のような内容の分からないファイル名は増やしません。

## カバレッジについて
ここでいうE2Eカバレッジはソースコードの行カバレッジ100%を意味しません。画面・機能・正常系・異常系・権限・ポップアップ・主要な境界値をテスト観点表と照合して網羅する方針です。機能追加時には観点表とテストを同時に更新します。
